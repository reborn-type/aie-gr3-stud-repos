## 2. Структура проекта

Проект организован в следующей структуре:

- `requirements.txt` – зависимости проекта (библиотеки Python, необходимые для запуска).
- `report.md` – отчёт по проекту (постановка задачи, данные, эксперименты, результаты).
- `self-checklist.md` – чеклист самопроверки проекта перед сдачей.
- `notebooks/` – экспериментальные ноутбуки:
  - EDA, прототипы моделей, отдельные эксперименты по метрикам (batch_size и lr).
- `backend/` - Все папки и файлы которые связанны с серверной частью сервиса и частью искусственного интеллекта.
- `src/` – основной код проекта:
  - модули для работы с данными;
  - обучение моделей;
  - запуск сервиса/скриптов.
- `src/models/` - Обучение основной модели сохранение ее инференса в artifacts, также описания жизненного цикла модели в рамках бекенда.
- `src/db/` - Модели Alembic для базы данных.
- `src/alembic/` - Необходимые зависимости для работы с Alembic.
- `src/controllers/` - Контроллеры для маршрутизации поступающих http запросов.
- `src/pydanticModels` - pydantic модели для форматирования запроса/ответа обращений.
- `data/` – учебные данные:
  - Открытый и обезличенный датасет по банковским обращениям на русском языке для обучения модели. 
- `configs/` – конфигурационные файлы:
  - `.yaml`, `.json`, `.env.example`
- `tests/` – pytest тесты.
- `artifacts/` – сохранённые модели, отчёты, результаты экспериментов.
- `frontend/` - Все папки и файлы связанные с организацией и запуском части frontend приложения.

Структура проекта немного отличается от базовой, т.к. помимо серверной части реализован еще фронтенд из-за этого пришлось разбивать на две разные папки.

## 3. Требования и установка ... 

### 3.1. Требования

- Python `>= 3.10`
- Node.js `>= 20`
- npm `>= 10`
- Docker Desktop
- Docker Compose
- Git
- PostgreSQL `>= 16` (Если запуск будет происходить без Docker)

### 3.2. Установка окружения

Примерный сценарий (можно адаптировать под ваш проект):

```bash
# Перейти в папку проекта
cd project
# Создать виртуальное окружение (опционально, но рекомендуется)
python -m venv .venv
# Активировать окружение:
# Windows:
.venv\Scripts\activate
# Linux / macOS:
source .venv/bin/activate

# Установить зависимости
pip install --upgrade pip
pip install -r requirements.txt

# Создать файл окружения и указать в нем свою базу данных
cp configs/.env.example configs/.env

# Применить миграции
cd src
python -m alembic upgrade head

# Либо если используется docer-compose из корня проекта (когда контейнеры уже подняты)

docker compose exec backend python -m alembic upgrade head
```

## 4. Как запустить проект


### 4.1. Запуск обучения модели

```bash
cd project/backend
source .venv/bin/activate 
python src/models/training.py    
```

### 4.2. Запуск сервиса (API/веб-интерфейс)

```bash
cd project
source .venv/bin/activate

# Запустить бекенд находясь в директории backend / 
python -m uvicorn app:app --reload --port 8000

# В отдельном терминале перейти в project/frontend/my-app/ 
cd project/frontend/my-app

# Установить зависимости npm
npm install

# Запустить фронтенд
npm run dev

# Чтобы запустить тесты находясь в папке project/backend 
python -m pytest
```

Или, если используется docker-compose:

```bash
cd project
docker compose up --build
```
